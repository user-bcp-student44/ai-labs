# HU-01: Proteger el token de autenticación

## Origen
- **Componente:** web
- **ID:** H-WEB-01
- **Hallazgo:** el token bearer continúa accesible a JavaScript del mismo origen, incluso tras el cambio a `sessionStorage`.
- **Evidencia:** `web/src/app/services/session.service.ts:12`; `web/src/app/dashboard/dashboard.component.ts:43`.

## Contexto
H-WEB-01 está marcado como Pendiente en HALLAZGOS.md. El almacenamiento actual reduce la persistencia del token, pero no evita que código JavaScript del mismo origen lo lea, por lo que permanece expuesto ante XSS.

## Ajustes necesarios
- Definir e implementar un mecanismo de sesión que evite que JavaScript del frontend pueda leer el token.
- Mantener el acceso autenticado a las tareas y los flujos existentes de inicio y cierre de sesión.
- Acordar los cambios necesarios entre login y consulta de tareas antes de implementarlos.

## Criterios de aceptación
- Una prueba de navegador confirma que JavaScript no puede leer el token de autenticación.
- Una prueba verifica que el token no se guarda en `localStorage` ni en `sessionStorage`.
- Una prueba funcional confirma que, después del login, la consulta de tareas continúa autenticándose correctamente.
- Una prueba funcional confirma que, después de cerrar sesión, una consulta posterior de tareas no conserva la autenticación.

## Evidencia esperada
- Resultados de pruebas automatizadas de sesión, login, consulta de tareas y cierre de sesión.
- Evidencia de navegador que confirme que el token no es accesible desde JavaScript.
- Diff local y documentación del mecanismo de sesión y de cualquier ajuste acordado para el flujo de autenticación.
